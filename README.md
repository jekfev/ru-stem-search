# 🔎 Russian Stem Search

**Нормальный русский поиск для WordPress: «дорога», «дороги» и «дорогу» наконец находят одно и то же.**

Стеммер Snowball + полнотекстовый индекс MySQL. Без внешних сервисов, без зависимостей, без правок темы.

## Зачем это нужно

Штатный поиск WordPress не знает русской морфологии. Для него «дорога», «дороги» и «дорогу» — три разных слова, и читатель, который вводит одно из них, теряет большую часть материалов. На реальном новостном сайте (архив около 15 700 статей):

| Запрос | Штатный поиск | Russian Stem Search |
|---|---:|---:|
| дорога | 380 | **1515** |
| дороги | 670 | **1515** |
| дорогу | 213 | **1515** |
| школа | 812 | **3242** |
| школы | 1376 | **3242** |

Вторая проблема — скорость. Штатный поиск делает `LIKE '%слово%'` по всему тексту всех записей, на большом архиве это около секунды и больше на каждый запрос. Здесь запрос идёт по готовому индексу:

| | Штатный поиск | Russian Stem Search |
|---|---:|---:|
| Время запроса (архив ~15 700 статей, обычный shared-хостинг) | ~0,9 с | **0,01–0,07 с** |

Третья — порядок. Статья, целиком посвящённая теме, должна стоять выше той, где слово мелькнуло один раз.

## Возможности

- **Морфология.** Любая форма слова находит все остальные. Русский стеммер Snowball написан на чистом PHP и входит в плагин, ничего ставить не нужно.
- **Любой порядок слов.** «ремонт дороги» и «дороги ремонт» дают одно и то же.
- **Поиск по началу слова.** Не нужно дописывать слово целиком.
- **«Фраза в кавычках»** ищется целиком, в нужном порядке.
- **Умное ранжирование.** Сначала статьи, у которых слово стоит в заголовке; дальше по релевантности с небольшим бонусом свежести; при равенстве — новее выше.
- **Мягкий запасной вариант.** Все слова запроса обязательны. Если ни одной записи с ними всеми нет, плагин покажет записи хотя бы с одним из слов, а не пустую страницу.
- **Мелочи, которые ломают поиск на русском сайте:** `ё` = `е`; служебные слова («и», «в», «на»…) отбрасываются; разреженные заголовки документов «П О С Т А Н О В Л Е Н И Е» склеиваются; номера («№ 125», «2024») ищутся точно.
- **Работает с любой темой.** Плагин подменяет результат любого запроса `WP_Query` с параметром `s`, шаблоны темы не трогает.
- **Индекс обновляется сам.** Опубликовали, изменили или сняли запись с публикации — индекс актуален.
- **Безопасное включение.** Пока индекс не построен, работает штатный поиск WordPress. Читатели не увидят пустую выдачу на время сборки.
- **Сборка индекса из админки** одной кнопкой (с прогрессом) или через WP-CLI.
- **Чистое удаление.** При удалении плагина исчезают и таблица, и опции.

## Установка

1. Скачайте архив репозитория, папку `ru-stem-search` положите в `wp-content/plugins/` и активируйте плагин.
   (Либо положите один файл `ru-stem-search.php` в `wp-content/mu-plugins/`: тогда плагин нельзя случайно отключить.)
2. Откройте **Инструменты → Русский поиск** и нажмите **«Построить индекс заново»**.
   Сборка идёт пачками по 200 записей; на архив в 15 тысяч статей уходит порядка полутора минут.
3. Готово: как только индекс собран, поиск на сайте включается автоматически.

Через WP-CLI:

```bash
wp sg-search rebuild                 # полная пересборка
wp sg-search rebuild --batch=300 --sleep=1   # бережнее к слабому хостингу
wp sg-search test дороги             # основы слов, число результатов, первые 10
```

## Как это работает

```
 статья ──► очистка HTML ──► слова ──► основы (Snowball) ──► таблица wp_sg_search
                                                                  │  FULLTEXT(title)
                                                                  │  FULLTEXT(title, body)
 запрос «дороги» ──► основа «дорог» ──► MATCH … AGAINST (BOOLEAN MODE) ◄┘
                                          │
                                          ▼
                    порядок: слово в заголовке → релевантность × свежесть → дата
```

1. **Индексация.** Для каждой опубликованной записи и страницы текст очищается от тегов и шорткодов, делится на слова, слова приводятся к основам. Основы заголовка и текста лежат в отдельной таблице `{prefix}sg_search` с двумя полнотекстовыми индексами InnoDB.
2. **Запрос.** Слова запроса проходят тот же путь. Каждое становится условием `+основа*` (все слова обязательны). Для длинных слов добавляется основа без последней буквы как целое слово: стеммер Snowball режет формы одного слова по-разному («урожай» → «урожа», «урожая» → «урож»), и без этого часть форм потерялась бы.
3. **Подмена.** Плагин перехватывает фильтр `posts_pre_query` на любом поисковом запросе фронтенда и сам отдаёт список записей, число найденных и число страниц. Пагинация темы продолжает работать.
4. **Короткие слова.** У InnoDB минимальная длина токена 3 символа, поэтому очень короткие основы дополняются служебным символом «ъ».

## Требования

- WordPress 5.0 или новее;
- PHP 7.1 или новее (код не использует ничего, что убрано в PHP 8.x);
- MySQL 5.6+ или MariaDB 10.0+ с таблицами InnoDB (поддержка `FULLTEXT`).

Проверено в работе: WordPress 6.4, PHP 7.1, MySQL 5.7. Синтаксис проверен на PHP 7.1, 7.4, 8.0 и 8.2.

## Вопросы и ответы

**Это заменит Relevanssi, SearchWP, Elasticsearch?** Нет, и не стремится. Это лёгкое решение для одной задачи: русская морфология и скорость на обычном хостинге. Нет страницы с весами и фильтрами, нет поиска по произвольным полям и таксономиям, нет синонимов.

**Что индексируется?** Заголовок, отрывок и содержимое записей (`post`) и страниц (`page`) со статусом «опубликовано», кроме защищённых паролем. Другие типы записей можно добавить в константу `SG_SEARCH_TYPES` в начале файла.

**Почему число результатов у «урожай» и «урожая» чуть отличается?** Это особенность алгоритма Snowball: он иногда режет формы одного слова до разных основ. Плагин сглаживает большинство таких случаев (см. «Как это работает», пункт 2), но не все.

**Почему «дороги» находит и «дорогие»?** Поиск идёт по основе слова с продолжением. Это цена полноты: лучше показать лишнее, чем потерять нужное. Статьи, где слово стоит в заголовке, идут первыми, так что шум оказывается в хвосте выдачи.

**Нагрузит ли плагин базу?** Индекс занимает порядка 1,5–2 размеров текста записей. Сборка идёт пачками с паузами; запросы после сборки быстрее штатных.

**Что с английским и другими языками?** Стемминг только для русского. Слова других языков, числа и латиница сохраняются как есть и ищутся по началу слова.

**Как вернуть штатный поиск?** Деактивируйте плагин, либо удалите опцию `sg_search_ready`.

## Разработка и вклад

Весь плагин лежит в одном файле `ru-stem-search.php`. Issue и pull request приветствуются: особенно примеры запросов, где результат вас не устроил.

Планы: страница настроек (типы записей, веса заголовка и свежести), вывод «Вы искали…» с подсказками при пустой выдаче, режим «только начало слова» для уменьшения шума.

<summary><b>English summary</b></summary>

**Russian Stem Search** is a lightweight WordPress search plugin for Russian-language sites. Default WordPress search does no morphology, so «дорога», «дороги», «дорогу» (three forms of the same word) return different result sets, and it scans post text with `LIKE`, which is slow on big archives.

The plugin stems Russian words with a pure-PHP Snowball implementation, stores stems in its own table with MySQL InnoDB `FULLTEXT` indexes, and replaces the front-end search query through `posts_pre_query`. Any word form finds all others, word order does not matter, titles rank higher than body text, and queries take ~0.01–0.07 s on a ~15,700-post archive (vs ~0.9 s for core search). Until the index is built, core search keeps working.

Install: copy to `wp-content/plugins/`, activate, then **Tools → Русский поиск → rebuild** (or `wp sg-search rebuild`). Requires WordPress 5.0+, PHP 7.1+, MySQL 5.6+/MariaDB 10+ with InnoDB. GPL-2.0-or-later.

</details>
